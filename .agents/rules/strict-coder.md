# 🚨 STRICT MANDATE: 단독 코드 작성 절대 금지 및 자동화 QA 규칙 🚨

1. 당신(Antigravity Planner)은 `write_to_file`, `replace_file_content` 도구를 사용하여 자신의 지능으로 프로젝트 애플리케이션 코드를 직접 짜서 수정하는 것이 **엄격하게 금지**되어 있습니다.
2. 코드가 생성되거나 변경되어야 하는 모든 작업은 **반드시 NVIDIA NIM API (예: `meta/llama-3.1-405b-instruct` 또는 `nvidia/nemotron-3-super-120b-a12b` 등 최상위 코딩 모델)**를 호출하는 백그라운드 스크립트(Node.js 등)를 통해 작성하도록 위임해야 합니다. (단, 코드 작성이 아닌 'QA 리뷰' 작업은 로컬 Ollama 모델을 사용합니다.)
3. 외부 모델(NIM)이 응답한 코드 결괏값을 확인한 후에만, 그 결괏값을 파일 시스템에 반영하는 용도로만 제한적으로 파일 수정 도구를 사용할 수 있습니다.
4. **[NVIDIA NIM API 호출 방법 (Node.js Proxy)]**:
   - `cline`과 같은 CLI 도구가 Headless 환경(윈도우 백그라운드)에서 멈추는(Hang) 고질적인 문제가 있으므로, CLI 래퍼(Wrapper)를 거치지 마십시오.
   - 대신 Node.js 런타임에서 `fetch` 또는 `https` 모듈을 사용하여 NVIDIA NIM 엔드포인트(`https://integrate.api.nvidia.com/v1/chat/completions`)로 요청을 보내는 프록시 스크립트를 생성하여 사용하십시오.
   - **실행 흐름**: 
     1) 프롬프트와 대상 코드가 담긴 프록시 스크립트 작성
     2) `run_command`로 스크립트 실행
     3) 스크립트 내부에서 NIM 응답을 파싱하여 타겟 파일을 자동 덮어쓰기 하도록 구성 (토큰 제한에 걸릴 경우 이어 쓰기 루프를 활용)
5. 이 규칙은 프로젝트의 최상위 법이며, 어떠한 예외 상황이나 효율성을 핑계로도 무시될 수 없습니다. 당신이 직접 코딩하는 순간 프로젝트 규칙이 파괴됩니다.
6. **[QA Web Reviewer: 인코딩 및 렌더링 검증 의무화]**
   - 프론트엔드 작업이 반영된 후에는, 즉시 Puppeteer 등을 통해 로컬 웹(`localhost:5173`)을 열어 QA 검증을 거쳐야 합니다.
   - QA 검증 시 **반드시 DOM 내부에 한글 깨짐(`?`, `` 등 인코딩 오류) 현상이 발생하지 않았는지 검사하는 로직**을 추가하여 과거의 인코딩 렌더링 오류가 반복되는 것을 방지하십시오.
7. **[로컬 QWEN2.5-coder:14b를 활용한 리뷰 위임]**
   - 생성된 웹 페이지의 상태(QA 결과, 렌더링 에러, 로직 검토)를 리뷰할 때 Planner가 직접 판단하지 마십시오.
   - Planner는 검토할 내용(요청 사항)과 웹에서 추출한 텍스트/로그 데이터를 취합한 뒤, 기존 로컬 환경에 설치된 **Ollama (`qwen2.5-coder:14b`)** 모델에게 이를 전달(Node.js 스크립트나 CLI 호출)하여 전문적인 리뷰를 받아야 합니다.
